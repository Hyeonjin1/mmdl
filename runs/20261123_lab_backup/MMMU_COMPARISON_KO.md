# MMMU 실험 결과 — 재채점, Lookback, NoWait

| 실험 | 비교 범위 | 대조군 → 변경 후 | 관찰한 결과 |
|---|---|---|---|
| 파서 v2 재채점 | 저장된 MMMU validation 900개 응답 중 미추출 객관식 46개 재검토 | 564/900 → 568/900 (62.67% → 63.11%) | 답 6개 추가 추출, 그중 정답 4개 |
| Lookback | 과거 길이 제한·미추출 40쌍 | 4/40 → 6/40 (10.0% → 15.0%) | 미추출 → 정답 2개 |
| Lookback | 과거 정상 종료 40쌍 | 21/40 → 19/40 (52.5% → 47.5%) | 정답 → 미추출 2개 |
| NoWait | 과거 길이 제한·미추출 40개 중 양쪽 채점 완료 37쌍 | 6/37 → 8/37 (16.2% → 21.6%) | 정답 획득 5개, 정답 손실 3개, 순증 2개 |

## 기존 응답 재채점

재채점은 저장된 응답의 최종 선택지를 복원한다. 모델 응답을 다시 생성하지 않았다. 원래 로컬 Qwen3-8B 채점에서는 537개 정답과 객관식 81개 미결이 기록됐다. 별도 Judge 재시도에서는 미결 81개 중 51개를 판정해 정답 566개와 미결 30개를 기록했다. terminal rules v1 분기는 원 채점의 미결 81개에 규칙을 적용해 35개를 추출하고 46개를 미추출 오답으로 처리해, 팀 스냅샷에서 563/900을 기록했다.

파서 v2는 자체 기준본에서 남은 46개를 검토했다. 모델 추론이나 Judge 신규 호출 없이 답을 6개 더 추출했다. 기존 Judge 제안과 응답 내 근거가 함께 뒷받침한 4개, 도표 라벨을 보기 내용으로 매핑한 1개, 선택지 문자와 보기 문구가 직접 일치한 1개다. 추가 추출 중 4개는 정답이고 2개는 오답이다. 남은 40개는 전부 길이 제한에 걸려 생성 종료 규칙에 따라 계속 미추출로 처리됐다. 이는 후속 생성 실험의 진단군이 됐다.

파서 v2 보고서의 기준은 564/900이고 팀 terminal rules v1 스냅샷은 563/900이다. 출처별 수치를 유지한다. 파서 v2 개선 폭은 자체 기준 대비 **+4개, +0.44%p**다. 로컬 채점 규약에서 정답은 최종 선택지와 정답표의 일치를 뜻한다. `scoring_unresolved=0`은 미추출이 점수상 오답으로 처리된 경우에도 성립한다. [팀 결과 및 parser v2 비교 자료 아카이브](archives/MANIFEST.json)

## Lookback — 생성 중 불확실성 문구에 개입

최근 50개 생성 토큰에서 공개된 발동 문구를 찾고, 답 단계 신호가 나오기 전이면 재검토 문구를 삽입한 뒤 동일 이미지와 앞선 출력 토큰으로 요청을 재개했다. 공개 발동·삽입 문구를 각각 10개씩 사용한 부분 재현이다. 80개 중 19개에 개입해 40회 삽입했고, 비개입 61개는 양쪽 응답과 종료 유형이 일치했다.

- **진단군**에서 전자공학 28번과 마케팅 23번이 미추출에서 정답으로 바뀌었다. 반복 중단은 10→6건, 길이 종료는 24→26건이었다.
- **정상 종료군**에서 기계공학 19번과 수학 21번이 정답에서 미추출로 바뀌었다. 생성은 정상 종료했고 정답 문자가 원문에 나왔으나, 여러 줄 수식이나 바뀐 보기 문구 때문에 고정 파서가 최종 선택지를 확정하지 못했다.
- 전체 정답은 양쪽 **25/80**이다. 진단군의 +2와 정상군의 −2를 함께 표시한다. 토큰을 표기할 때는 생성 토큰과 삽입 토큰을 구분한다. 요청 재개 시 RNG와 presence penalty 이력이 초기화될 수 있고, 캐시·재요청 비용은 출력 토큰 수만으로 드러나지 않는다.

초기 smoke의 C 컴파일러 부재와 조건 사이 KV 캐시 재사용 문제는 환경 및 캐시 격리를 적용해 해결했다. [실행·채점 설정 및 실패 기록](results/mmmu_lookback_pilot_20261123/experiment.md) · [집계 JSON](results/mmmu_lookback_pilot_20261123/summary.json) · [재현 아카이브](lookback-reproduction.tar.gz)

## NoWait — 생성 중 토큰 차단

`wait`, `however`, `check` 등 고정 키워드를 대소문자 구분 없이 부분 문자열로 포함하는 토큰을 vLLM logits processor로 매 생성 단계에서 차단했다. 그 결과 다른 단어 일부도 차단된다. 진단군 40개 ID는 Lookback 진단군과 일치한다. 기존 생성·채점 5쌍을 동일한 체크포인트 계약으로 복원했고, 별도 Student/Judge smoke 후 남은 35문항을 생성했다. 새 smoke의 Accounting 22번은 프롬프트·이미지·샘플링이 일치했지만 이전 실행과 종료 유형이 달랐다.

| 지표 | Baseline | NoWait |
|---|---:|---:|
| 생성 / 채점 완료 | 40 / 38 | 40 / 38 |
| 양쪽 채점 완료 37쌍의 정답 | 6/37 | 8/37 |
| 40문항 생성 토큰 합계 | 256,173 | 245,360 |
| 길이 종료 | 24 | 20 |
| 반복 중단 | 8 | 4 |

40문항의 생성 토큰은 **10,813개 감소(−4.22%)**했다. NoWait 차단 토큰 위반은 0건이다. 채점 완료 37쌍에서 NoWait만 맞힌 건축·공학 18번, 전자공학 14번, 에너지·동력 17번, 기계공학 8번, 음악 25번 중 4개는 대조군이 최종 답을 남기지 못했다. 대조군만 맞힌 문항은 재료 20번, 기계공학 4번, 음악 27번이다. 기계공학 4번은 NoWait가 길이 제한에 걸렸다.

3문항에서 조건별 채점 4건이 보류됐다. Judge가 객관식 선택지 문자 대신 답안 텍스트를 반환했고 고정 규칙으로 선택지를 확정하지 못했다. 같은 조건으로 해당 4건만 다시 채점했지만 `Invalid option`이 재현됐다. 기존 계약을 유지한 채 40문항 기준 가능한 정확도를 범위로 표시하면 Baseline **15–20%**, NoWait **20–25%**, 두 조건 차이는 **0~+10%p**다. ## 표와 발표에서 주의할 점

- **재채점과 생성 개입의 분모를 표시한다.** 900문항 재채점은 같은 출력을 다른 채점 규약으로 읽은 결과다. Lookback 80문항과 NoWait 40문항은 과거 종료 상태로 고른 파일럿이다. 세 증감치를 합산하거나 MMMU 전체의 모델 성능 향상으로 일반화할 근거는 없다.
- **각 파일럿의 자체 대조군을 붙인다.** 두 파일럿의 진단 ID는 같지만 Lookback은 16,384 컨텍스트에서 고정 파서로, NoWait는 49,152 Student 컨텍스트에서 Qwen3-8B Judge와 terminal rules로 평가했다. 정확도를 직접 비교해 두 방법의 우열을 정하려면 공통 대조군·생성 설정·채점 규약이 필요하다.
- **정답·오답·미추출·채점 보류를 표시한다.** 고정 규약상 오답으로 집계한 미추출과 채점이 아직 판정되지 않은 응답은 집계에서 다르게 다룬다. NoWait에는 37쌍 정확도와 40쌍 생성량이 함께 나오므로 각 분모를 적는다. Lookback 사례처럼 파서의 미추출과 최종 선택지의 실질적 오류도 구분한다.
- **변화 방향과 비용을 함께 적는다.** 순증 2개에 가려진 획득 5·손실 3을 표시한다. 생성 토큰 절감률을 전체 지연이나 GPU 비용 절감률로 바꿔 부를 근거는 없다. Lookback의 삽입·재요청과 채점 비용까지 포함하려면 별도 계측이 필요하다.
- **재현 범위를 적는다.** 팀 checkout은 `1c4d7b32ab254d8444b401b06750dfb6e2bfca9e`, Student는 Qwen3-VL-4B-Instruct, 생성 seed는 3407, 생성 상한은 8,192토큰이다. Lookback은 삽입 토큰도 상한에 포함한다. 실행 파일·모델 리비전·입력 및 코드 해시는 연결한 설정과 아카이브에 남아 있다.
