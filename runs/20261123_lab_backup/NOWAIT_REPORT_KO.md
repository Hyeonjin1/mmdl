# MMMU NoWait 및 답안 전환 보고서

과거 팀 B0에서 8,192토큰 한도에 도달했고 Parser v2로도 최종 선택지를 추출하지 못한 객관식 40문항을 재추론했다. **NoWait으로 정답 8건**, **NoWait에 4,096토큰 답안 전환을 적용해 정답 19건**을 확인했다.

## 객관식 40문항 결과

| 조건 | 확인된 정답 | 채점 보류 | 생성 토큰 | 과거 B0 대비 감소율 | 길이 종료 / 반복 중단 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 과거 팀 B0 | 0/40 | — | 327,680 | — | 40 / 0 |
| NoWait | 8/40 | 2 | 245,360 | 25.12% | 20 / 4 |
| NoWait · 차단 목록 정제 | 8/40 | 2 | 244,736 | 25.31% | 22 / 5 |
| **NoWait · 4,096토큰 답안 전환** | **19/40** | **1** | **143,648** | **56.16%** | **0 / 0** |

채점 보류는 확인된 정답 수에 포함하지 않았다. 생성 토큰은 조건별 40문항 전체의 출력 합계다.

NoWait에서 정답을 확인한 8문항의 생성량은 과거 B0 65,536토큰에서 24,995토큰으로 줄었다(−61.86%).

## 적용 방법

Qwen3-VL-4B-Instruct의 생성 과정에서 자기검토 표현과 철자가 겹치는 토큰의 로짓을 억제했다. MMMU validation 고정 리비전 `876ce5cb130f7f7e290ce4d9984357737d4db5cf`에서 이미지를 복원했다. 과거 B0 기록과 문항 ID, 이미지 이름·순서, 입력 토큰 개수를 대조했다. 새 응답은 Qwen3-8B Judge와 최종 답 추출 규칙으로 채점했다. 과거 B0와 NoWait의 수치는 저장 응답과 재추론 응답의 비교다.

- 차단 목록 정제는 디코드 후 공백과 대소문자를 정규화해 사전 고정 예외 (anyone, button, company, know, knowledge, mother, ohio)에 정확히 일치하는 토큰만 제외했다. 마스크는 918개에서 886개로 줄었다. 생성 예산과 채점 조건은 NoWait 설정을 따랐다.
- 답안 전환은 918개 원래 마스크에서 4,096토큰 한도까지 첫 요청을 실행한다. 그 전에 종료하면 기존 흐름을 유지하고, 한도에 도달하면 원래 이미지와 생성 토큰을 붙여 최종 선택지만 요청한다. 추가 생성 한도는 128토큰이다. 이어받은 멀티모달 프롬프트의 토큰을 대조했다. 전환 후에는 두 번째 요청의 출력으로 답을 채점했다.
- 답안 전환은 29문항에서 발동했다. 재요청 지시문은 합계 1,102 입력 토큰이며, 재요청 프롬프트에는 이미지와 기존 생성 토큰을 포함해 합계 156,034 입력 토큰이 들어갔다. 이 입력 비용은 표의 생성 토큰에서 제외한다.

## 답안 전환으로 확인한 정답 19건

- NoWait에서도 확인한 정답 8건을 유지했다.
- NoWait에서 채점 보류된 건축·공학 26번과 재료 9번에서도 정답을 확인했다.
- 나머지 9건은 회계 22번, 건축·공학 9번, 전자공학 7번, 에너지·전력 4번·8번·9번, 재료 22번, 수학 16번, 음악 23번이다.

답안 전환에서는 에너지·전력 13번이 채점 보류로 남았다. 차단 목록 정제의 보류 문항은 건축·공학 26번과 재료 9번이었다.

## 발표 슬라이드용 베이스라인 반영 결과

첨부 슬라이드의 과거 B0 집계 **563/900(62.56%)**를 출발점으로 삼았다. 기존 답 추출 실패 46문항 중 과거 B0에서 토큰 상한에 도달한 객관식 40문항의 판정만 각 실험 결과로 대체했다. **NoWait 기본 적용은 571/900(63.44%)**, **4,096토큰 답안 전환까지 적용하면 582/900(64.67%)**이다. 답안 전환의 정답 19건에는 NoWait 기본 정답 8건이 포함된다. Parser v2의 미추출 목록은 대상 선정에 사용했고, 전체 점수는 슬라이드의 과거 B0 채점본에 합산했다. 주관식 53문항에는 과거 B0 판정을 사용했다.
